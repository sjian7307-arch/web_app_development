# 產品需求文件 (PRD)

## 1. 專案概述
- **背景與動機**：舉辦活動時，主辦方經常需要處理大量的報名資訊、確認繳費狀態以及回覆參加者的疑問。為了簡化這些繁瑣的管理流程，本系統提供一個集中的平台來處理活動發布與報名管理，從而減輕主辦方的負擔。
- **目標用戶**：舉辦活動的人（活動主辦方）。
- **核心價值主張**：提供一個直覺、高效的活動與報名管理工具，讓主辦方能輕鬆掌握參與人數、費用狀態及活動行程，專注於活動本身的品質。

## 2. 功能需求
以下列出本系統的主要功能，並以使用者故事呈現：

- **報名功能**
  - 作為活動主辦方，我希望系統能提供線上報名表單，以便參加者可以直接填寫資料報名。
- **統計人數**
  - 作為活動主辦方，我希望系統能自動統計並顯示當前的報名總人數，以便我隨時掌握活動參與狀況，決定是否額滿。
- **繳費管理**
  - 作為活動主辦方，我希望系統能紀錄每位參加者的繳費狀態（未繳費/已繳費），以便我清楚知道誰已經完成付款。
- **顯示行程**
  - 作為活動主辦方，我希望能在系統中建立並展示詳細的活動行程表，以便參加者隨時查看活動的具體安排。
- **顯示報名狀態（成功與否）**
  - 作為活動主辦方，我希望系統能在參加者提交報名後，清楚顯示報名是否成功，以便減少參加者的疑慮和後續的人工詢問。

## 3. 非功能需求
- **技術限制**：
  - 系統後端使用 **Flask** 框架。
  - 前端渲染使用 **Jinja2** 模板。
  - 資料庫使用 **SQLite** 進行輕量級資料儲存。
- **效能與安全考量**：
  - **資料安全**：妥善保護參加者的個人資料（如姓名、聯絡方式）。
  - **併發處理**：在活動報名熱門時段，需確保同時報名人數不會超過限制，避免超收。
  - **操作體驗**：頁面載入速度需快速，提供良好的行動裝置瀏覽體驗（RWD）。

## 4. MVP 範圍 (Minimum Viable Product)
- **Must Have (必須有)**：
  - 主辦方可以建立活動並填寫行程表。
  - 參加者可以填寫報名表單。
  - 主辦方後台可查看報名名單與總計人數。
  - 參加者提交表單後能立即看到報名成功或失敗的狀態畫面。
- **Should Have (應該有)**：
  - 報名名單上的繳費狀態標記（主辦方可手動更新狀態）。
- **Nice to Have (最好有)**：
  - 串接第三方支付金流，實現自動確認繳費狀態。
  - 報名成功自動發送確認 Email 或簡訊給參加者。
